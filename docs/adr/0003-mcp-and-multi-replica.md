# 0003：外部工具走 MCP，多副本按边界切组件

## 背景

Agent 需要调外部系统（WMS/ERP 等），同时服务要能水平扩容。

## 决策

- 外部工具按 MCP 协议接入：对端暴露工具，服务端一套加载逻辑通吃；新增系统改配置，不改 agent 代码；
- 多副本用 `docker compose --scale app=N` + nginx 轮转；
- nginx `proxy_pass` 用变量式 + resolver，避免缩容后打到已销毁副本；
- SSE 关闭 `proxy_buffering`，保证逐字输出。

## 结果

- 工具接入成本从"每家写适配"变成"配置加一行"；
- 扩容后限流、记忆、向量库、缓存都正确；
- 代价：MCP 首次握手有冷启动，启动时后台预热；stdio 只能同机，跨机要改 http。

## 被否方案

- 每个系统写一个函数：接第五家时 agent 代码不可维护；
- 单副本不做共享状态：扩容后状态全部失效。
